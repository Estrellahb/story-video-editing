# 故事视频剪辑与发布交付

用中文沟通。收到未剪辑素材后，按“确认需求 → 梳理素材 → 确认故事链 → 剪辑与字幕 → 导出检查 → 交付 → 选择上传平台”完成工作。用户当次指定的参数优先于以下默认值；已确认的信息不要重复询问。

## 默认参数

| 项目 | 默认值 |
| --- | --- |
| 画幅 | 横版 16:9 |
| 分辨率 | 1920×1080 |
| 帧率 | 60 fps |
| 字幕字体 | 思源黑体简体中文 Bold（Source Han Sans SC Bold） |
| 字号 | 48，以 1920×1080 字幕画布为基准 |
| 字幕颜色 | 白色 #FFFFFF |
| 字幕描边 | #009AFF，3 像素 |
| 字幕位置 | 底部居中，避开关键画面和界面信息 |
| 成片叠加文字 | 仅对白字幕；不加段落标题、标注标题、开场片名或搞笑旁注 |
| 视频导出格式 | 与原素材相同的封装格式及扩展名 |
| 封面 | 16:9 与 4:3 各一张，默认 PNG |
| 上传平台 | B站（哔哩哔哩） |

## 1. 确认需求与素材边界

先查看素材文件及媒体信息，并集中补齐影响剪辑的缺失信息：

- 剪辑风格：例如朋友互动搞笑、完整剧情、温暖冒险、紧凑集锦。可以根据素材提出建议，但最终以用户确认的风格为准。
- 素材从哪里到哪里：记录每个源文件的文件名、开始时间码、结束时间码；多文件时同时确认顺序。时间码统一用 HH:MM:SS，必要时附毫秒。用户以事件描述边界时，先定位到具体时间并供其确认。
- 成片预计多长：确认目标成片时长或范围；另外估算分析、剪辑、字幕校对和渲染的工作耗时，明确区分成片时长与制作耗时。估计应依据素材长度、机器及工具情况，不承诺没有依据的完成时间。
- 朋友名字：确认简介需要出现的姓名或昵称及准确写法。可先从可靠的既有记录整理候选，不凭模糊语音猜名字。

默认画幅、字幕等可以直接列在方案中，无需逐项再问。尚未确认剪辑风格、素材边界或目标时长时，继续做媒体检查和素材梳理；这些信息确定前不定稿剪辑。朋友名字缺失不妨碍素材分析，但最终文案交付前必须补齐。

检查原素材的时长、画幅、帧率、视频与音频编码、音轨及封装格式。默认 1080p/60 fps 指最终输出规格，不代表低帧率素材转换后会产生真实的额外动作细节。需要裁切时避免丢失主体、关键动作或游戏界面信息。

## 2. 梳理并确认故事链

结合实际画面、原声和转写记录理解素材，不仅依赖自动字幕挑笑点。先识别人物、目标、行动、困难、转折、结果和收尾，再选择片段。

向用户给出具体、可审阅的剪辑方案：

1. 一句话说明故事主线及剪辑风格。
2. 用箭头串起完整故事链，例如“建立目标 → 尝试 → 遇到困难 → 调整策略 → 合作或冲突 → 结果 → 收尾”。按实际内容组织，不强行套齐所有节点。
3. 每个节点列出源文件与起止时间码、预计保留秒数，以及该段的铺垫或推进作用。
4. 汇总预计成片时长，并指出缺失铺垫、听不清的对白或不确定的结果。

确保观众理解“为什么做、做了什么、发生了什么、最后怎样”。保留后续结果所依赖的前置目标、道具、计划、失败原因及关键对话。删去重复等待、无进展操作和冗余对白，不能把因果关系一起删掉。

冷开场或重新排列片段只有在适合已确认风格、不会歪曲事实且能补回必要背景时才使用。笑点应有足够语境；结尾保留行动结果和人物反应，不能在关键结果出现前突然结束。故事超出目标时长时，给出保持完整性所需的时长或压缩方案，不自行舍弃关键结局。

先取得用户对故事链及方案的确认，再进入正式剪辑和最终渲染。既有确认覆盖的部分直接执行；改动故事范围、主线或关键结局时，更新方案并确认受影响部分。

## 3. 剪辑与字幕

保留玩家、朋友及环境或游戏原声，调整整体响度和剪口的短淡入淡出，避免削掉对白开头结尾。音乐、音效、变速或夸张转场按已确认风格使用，不默认添加。

字幕按最终剪辑时间线重新计算时间码，校对人名、游戏名、道具名、断句、多人重叠对白和关键剧情。不把无法确认的识别结果写成确定事实，也不用旁注补造剧情。本次既有偏好是字幕不显示“我操”等粗口，保留该句其他有意义内容与原声；用户当次另有要求时覆盖。

使用实际的思源黑体 Bold 字体文件，不能只写字体名却让渲染器悄悄替换。优先检查现有字体；字体缺失时解决字体来源或向用户说明再处理，不默默改用其他字体。检查长句换行、文字遮挡及字号可读性。

把指定字幕样式烧录进视频，同时交付独立 SRT。SRT 只保存对白和时间码，不携带字体、字号、颜色或描边；样式用编辑器或工作区内的 ASS 中间文件应用。使用 ASS 时，白色为 &H00FFFFFF，#009AFF 描边为 &H00FF9A00，Outline 为 3，字幕画布为 1920×1080。确认画面没有后加的片名、章节标题或旁注；原素材中的界面文字不因此删除。

## 4. 导出与检查

“与原素材相同格式”默认指封装格式及扩展名，如 MP4 输入导出 MP4、MKV 输入导出 MKV；不要强制所有视频导出 MP4。视频与音频编码优先沿用源素材兼容的编码，满足 1080p/60 fps 及字幕渲染需求；烧录字幕需要重新编码，不能承诺视频流无损复制。

多源文件格式不同且用户未指定时，在剪辑方案中说明冲突并确认最终格式。实际上传平台不支持原封装或编码时，说明具体限制并确认转换方案，保留同原格式的交付主文件。仅在本次需要核实平台限制时查询当前官方规则，不凭记忆套用限额。

导出后检查：

- 实际封装、分辨率、60 fps、时长及音轨，完整解码没有报错。
- 回看片头片尾、故事转折及剪切口，确认因果清楚、结局完整、无黑帧、音画同步且没有爆音。
- 核对烧录字幕的字体、字号、白字及蓝色描边，抽查长句和多人对白。
- SRT 使用成片时间码，序号和时序正确，字幕不超出片长，且与烧录内容一致。

保存原素材和既有版本，修改成片时使用明确版本名。

## 5. 最终交付

每个最终视频交付五个文件，使用同一主题名称并集中放在交付目录：

```text
视频主题.<与原素材相同的扩展名>
视频主题.srt
视频主题.txt
视频主题_16比9.png
视频主题_4比3.png
```

TXT 用 UTF-8，包含以下内容：

```text
视频标题：与实际成片内容一致的标题
标签：游戏或主题名称，朋友联机，其他相关关键词
简介：包含朋友名字、剪辑GPT，以及对本片故事的简短介绍。
```

标签必须是纯文字关键词，用逗号分隔，不加 #、话题符号、链接或 HTML。简介正文整体控制在 100 字以内，包括朋友名字和“剪辑GPT”，标题和标签不计入简介字数。名字以确认的写法为准，不填虚构人物。检查标题、简介和封面指向最终版本的故事；扩展剧情后同步更新，避免沿用旧版本主题。

两张封面表达同一故事和视觉风格，默认分别为 1920×1080（16:9）和 1920×1440（4:3）。按需要调整构图、裁切或扩展背景，避免拉伸主体或切掉标题、人物及关键物件。封面文字不受成片“仅对白字幕”的限制。使用真实成片截图或符合实际内容的视觉素材；如采用 AI 生成或编辑图片，使用当前可用的 imagegen 技能及其工具。

ASS、剪辑点、时间线、日志和转写记录放工作目录，不替代或混入必需的五件交付。用户要求工程文件时再另行交付。

## 6. 选择上传平台

交付完成后明确标注默认上传平台为 B站，允许用户改选其他平台。用户已经指定平台时直接沿用，不重复询问。准备与选定平台对应的标题、纯文字标签、简介及合适的封面。

选择平台和准备文件不等于已获授权上传；只有用户实际要求上传或发布时，才执行相应动作。提交前检查当前视频、字幕、文案、封面及账号对应关系；成功后提供真实的上传或发布状态及结果链接，失败时说明具体原因，不能声称已经发布。

## 本机已有资源

在当前机器上可优先检查以下路径；其他环境不存在时使用当前工作目录及可用工具：

- 素材根目录：`E:\video`，另有 `E:\video\素材`。
- 工作目录：`E:\video\剪辑工作`。
- 历史成片：`E:\video\剪辑成片`；历史封面：`E:\video\封面`。
- 字体：`E:\video\剪辑工作\fonts\SourceHanSansSC-Bold.otf`，同目录有许可证。
- 工作目录已有分析、转写、剪辑、字幕及检查脚本。复用前检查输入路径、片段范围、字幕样式、标题旁注开关与输出封装；旧脚本可能含过时的微软雅黑、浅蓝描边、固定 MP4 或固定故事范围，不能直接沿用这些默认值。

最终向用户报告实际成片时长、五个交付文件的位置、采用的导出格式与默认或已选平台。任何未解决的字幕、故事完整性或导出问题应明确说明。
